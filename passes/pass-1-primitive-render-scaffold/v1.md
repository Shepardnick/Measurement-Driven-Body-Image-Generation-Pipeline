# Pass 1: Primitive render scaffold

**Status:** v1 — auto-approved by user (feedback round skipped on user request)

## Goal

Stand up an end-to-end `target_measurements.json → posed humanoid mesh → 8-view PNG renders` pipeline using primitive shapes (ellipsoids + capsules) in place of SMPL-X. The output is scaffolding the rest of the project plugs into.

## Context

Why now: pre-pass investigation surfaced three blockers on the design doc's "real" Stage 2 path:

1. **SMPL-X weights are gated** behind academic registration the user hasn't completed.
2. **Stage 2A's primary path is broken as written.** SMPL-Anthropometry is NumPy-only and not differentiable through PyTorch, so backprop from measurement loss to β doesn't work with that library.
3. **Stage 2B's code is fabricated.** A2B expects 34 measurements (not 36), in meters (not cm), via a CLI (`python -m anthro.inference`), not a `from_pretrained()` Python API.

Standing up SMPL-X first would block on all three. A primitive proxy decouples them: the rendering loop, the 8-view geometry, the I/O scaffolding, the pose handling, the measurement validation — all transfer directly to the real SMPL-X pipeline later, but none of them needs gated weights or a working differentiable measurer to be built and tested now.

What this depends on: Python 3.10+, numpy, trimesh, pillow, matplotlib. (pyrender was attempted; PyOpenGL refused to build against this environment's setuptools. Matplotlib's 3D backend is the chosen renderer for primitives.)

What depends on this: pass 2 swaps the primitive body builder for SMPL-X (once weights land). Pass 3 adds A2B-driven β fitting using the verified CLI. Pass 4 adds anthropometric verification. Later passes add Nano Banana integration. The render module, file layout, pose vector, and measurement loader from this pass survive.

## Approach

Files created:

- `src/__init__.py` — empty package marker
- `src/measurements.py` — load `target_measurements.json`, run sanity checks from §4.3 of the design doc, return a typed dict
- `src/proxy_body.py` — `build_proxy_body(measurements, pose)` → `trimesh.Trimesh`
- `src/render.py` — `render_views(mesh, output_dir, angles, resolution)` writes one PNG per angle
- `src/main.py` — wire it: load → build → render → done
- `target_measurements.json` — canonical body from §2.1 of the design doc, cm units
- `outputs/.gitkeep`
- `requirements.txt`

Primitive body construction (`proxy_body.py`):

- **Torso:** two-segment ellipsoid stack. Upper (chest): radii from `bust_cm/(2π)` (lateral) and `chest_depth_cm/2` (anterior-posterior). Lower (waist): radii from `waist_cm/(2π)` and `waist_depth_cm/2`. Heights derived from `sitting_height_cm` minus head/neck offset.
- **Hips/pelvis:** ellipsoid below the waist taper, radii from `hip_cm/(2π)` and `hip_depth_cm/2`.
- **Head:** sphere, radius from `head_circ_cm/(2π)`.
- **Neck:** short cylinder, radius from `neck_circ_cm/(2π)`.
- **Arms:** two capsules per side. Upper arm length from `arm_length_cm × 0.45`, radius from `upper_arm_circ_cm/(2π)`. Forearm length `arm_length_cm × 0.55`, radius from `forearm_circ_cm/(2π)`.
- **Legs:** thigh capsule from `inseam_cm × 0.48` and `thigh_circ_cm/(2π)`. Calf capsule from `inseam_cm × 0.52` and `calf_circ_cm/(2π)`.

Assembled via per-primitive `trimesh.transformations` matrices then `trimesh.util.concatenate`.

Pose: applied as 4×4 rigid transforms on each limb primitive before concatenation. v1 pose = relaxed standing: shoulders rotated ~60° to bring arms ~15° from torso, slight elbow bend. Hardcoded in `main.py`; pose vector representation will get richer in later passes.

Rendering (`render.py`):

- Matplotlib 3D backend (`mpl_toolkits.mplot3d.art3d.Poly3DCollection`)
- Orthographic-ish projection, camera orbits at fixed distance and height
- 8 angles: 0°, 45°, 90°, 135°, 180°, 225°, 270°, 315°
- 1024×1024 PNGs, white background, neutral skin-tone face color, soft directional shading via `LightSource.shade`
- Outputs to `outputs/renders/view_<deg>.png`

Sanity checks (`measurements.py`): warnings only, never blocking. W/H ∈ [0.4, 1.0], stature ∈ [140, 210] cm, BMI ∈ [16, 35], bust > underbust > waist, hip > waist.

## Alternatives considered

1. **Start with real SMPL-X.** Rejected: blocked on gated weights + the doc's two broken stages. Highest-friction first step.
2. **A2B inference with zero-β SMPL-X.** Rejected: still needs gated weights, still needs A2B working in this environment, still doesn't exercise rendering — the scaffolding chunk that's most reusable.
3. **Nano Banana integration first.** Rejected: Nano Banana consumes the rendered references. No references → nothing to integrate.
4. **pyrender for rendering.** Attempted; PyOpenGL wheel build fails on this Ubuntu 24.04 / Python 3.11. Matplotlib is the working substitute. pyrender can be swapped back in later if/when SMPL-X meshes need photorealistic rendering.

## Risks & open questions

- **Matplotlib 3D rendering is geometrically correct but visually crude.** That's acceptable for pass 1; pass 2+ may need to revisit if/when meshes get realistic. The Nano Banana integration pass will need pretty renders, not these.
- **Primitive proportions are approximate.** A capsule scaled to "thigh circumference / 2π" treats the thigh as a perfect cylinder. Real thighs aren't. For scaffolding this is fine; the actual measurements verification doesn't happen until SMPL-X is in.
- **No joint smoothing between primitives.** Visible seams at shoulder/hip/etc. Acceptable for v1.

## Acceptance criteria

- `python3 -m src.main` runs to completion with zero errors from a clean state
- `outputs/renders/view_000.png` … `view_315.png` exist, 1024×1024
- Front view (`view_000.png`) shows a recognizable humanoid silhouette: head on top, torso, arms at sides, legs below, recognizable hourglass (narrow waist, wider hips)
- Sanity-check warnings fire correctly when given a measurements file that violates the constraints
- `target_measurements.json` reflects the §2.1 body
