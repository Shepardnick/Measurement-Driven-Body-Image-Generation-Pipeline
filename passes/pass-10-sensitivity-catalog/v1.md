# Pass 10: Morph-to-measurement sensitivity catalog

**Status:** v1 — auto-approved, executing.

## Goal

For every CharMorph slider, produce a numeric table showing how much each body measurement changes when the slider goes from 0 → 1, evaluated at the default mesh.

End artifact: `data/charmorph_morph_sensitivity.json`:

```json
{
  "Waist_Size": {
    "stature_cm": 0.01,
    "bust_cm": 0.0,
    "waist_cm": +3.42,
    "hip_cm": 0.0,
    "thigh_circ_cm": +0.3,
    ...
  },
  "Pelvis_GluteusMass": {...},
  ...
}
```

Plus a human-readable Markdown summary:
- Per-region table of slider → measurement sensitivities
- For each measurement: top-5 most-influential sliders (i.e., "to grow your waist, these are the levers")

Also expand the measurement layer to cover **thigh, knee, calf circumferences** since `target_measurements.json` has them and the pipeline currently doesn't measure them.

## Approach

### Stage 1 — Add thigh/knee/calf landmark rings

Extend `scripts/build_charmorph_landmarks.py` and re-run. New rings at canonical Y fractions of the default body:
- Mid-thigh: 35–40% of stature (between hip and knee)
- Knee: ~25% of stature
- Mid-calf: ~13% of stature
- Use the same convex-hull-in-Y-band trick; restrict X to leg-relevant range so we don't catch the other leg

### Stage 2 — Add corresponding measurements to `measure_torch`

For each new ring, perimeter computation same as bust/waist/hip. Output keys: `thigh_circ_cm`, `knee_circ_cm`, `calf_circ_cm`.

### Stage 3 — Build sensitivity catalog (`scripts/build_morph_sensitivity.py`)

```
default_measurements = measure(default_mesh)
for each slider in catalog:
    morph_values = {slider: 1.0}
    mesh = forward(morph_values)
    measurements = measure(mesh)
    sensitivities[slider] = {m: measurements[m] - default[m] for m in measurements}
```

165 sliders × ~10 measurements × forward pass (~100 ms each) = ~15-20 s total.

### Stage 4 — Write JSON + Markdown

- `data/charmorph_morph_sensitivity.json`: full table
- `passes/pass-10-sensitivity-catalog/morph_sensitivity.md`:
  - Top-10 morphs per measurement
  - Per-region tables showing nonzero sensitivities
  - Inverse lookup: for each measurement, "to change by X cm, push slider Y by X/sensitivity"

## Alternatives considered

1. **Autograd Jacobian** (one shot). Cleaner mathematically. But `clamp(v, min=0)` at v=0 has zero gradient — same issue as the fitter init bug. Finite differences (eval at v=0 and v=1) sidesteps this.
2. **Multi-point sensitivities.** Evaluate at multiple baseline values (0, 0.3, 0.7) to capture nonlinearity from combo-morph clamps. Useful for combo pairs but doubles/triples the compute and complicates the table. v1: single-point (0→1) sensitivity. Note nonlinearity in caveats.
3. **Pairwise combo sensitivities.** For combo pairs (Mass+Tone), record the 4-corner-blend behavior. Complex. v1: report each member independently with a note that paired sliders interact.

## Risks & open questions

- **Combo morph sliders won't fire at v=0.** When the user sets only `Mass=1.0` with `Tone=0`, the bilinear blend math gives `max(1*1 + 0*(-1), 0) = 1` for the max-min corner only. So the sensitivity table will capture the "Mass at 1 with everything else at 0" behavior correctly.
- **Some sliders might appear to have zero sensitivity** because the storage is empty (like `Body_Size_max`). Document these as inert in the catalog.
- **Thigh/knee/calf rings on a default mesh might overlap with arms** at certain Y heights (default mesh has arms in A-pose-ish posture, arms dangle near hips). Mitigate by restricting band X-range.
- **Sensitivities are evaluated at default mesh**, not at the user's current configuration. At extreme morph values the local sensitivity differs from the default-evaluated value. Note this in the doc.

## Acceptance criteria

- `data/charmorph_landmarks.json` updated with `thigh_ring`, `knee_ring`, `calf_ring` (and corresponding left/right indices if needed).
- `measure_torch` returns `thigh_circ_cm`, `knee_circ_cm`, `calf_circ_cm`.
- `data/charmorph_morph_sensitivity.json` covers ≥150 sliders × ≥8 measurements.
- `passes/pass-10-sensitivity-catalog/morph_sensitivity.md` lists top-10 sliders per measurement and per-region tables.
- Sanity check: `Waist_Size` is top-5 for `waist_cm`; `Pelvis_GluteusMass`/`Mass` top-5 for `hip_cm`; `Torso_BreastMass` top-5 for `bust_cm`. If any of these aren't top-5 something's wrong with measurement definitions.

## Out of scope

- Pairwise combo-morph sensitivity tables.
- Sensitivity tables evaluated at non-default baselines.
- Sensitivity for face/expression morphs against body measurements (would be all zeros).
- Programmatic inverse solver (using sensitivities to analytically solve morph values for a target). Useful future work; deferred.
