# Pass 2: External library adapters

**Status:** v1 — auto-approved by user (feedback round skipped on user request)

## Goal

Stand up working adapters for the two external libraries the design doc misdescribes: `kaulquappe23/a2b_human_mesh` (measurements → β) and `DavidBoja/SMPL-Anthropometry` (mesh → measurements). After this pass, pass 3 can integrate SMPL-X without simultaneously debugging two upstream library APIs.

## Context

Pre-pass-1 web verification confirmed both repos exist but the design doc's code skeletons don't match their real APIs:

- **A2B** expects 34 measurements in meters via a CLI (`python -m anthro.inference --measurements <json>`), not 36 measurements in cm via a fictional `A2BModel.from_pretrained(...)`.
- **SMPL-Anthropometry** is NumPy-based and not differentiable. Real API is `MeasureBody(...).from_verts(verts)` followed by `.measure(names)`, not `Measurer(...).measure_from_vertices(vertices, names=...)`.

If pass 3 (SMPL-X integration) tried to use the doc's fictional APIs directly, we'd be debugging upstream libraries plus pose plus weights plus rendering simultaneously. This pass isolates the upstream-library work so pass 3 has a clean surface to build against.

What this depends on: pass 1's `src/` scaffold; internet access to clone the repos; whatever Python deps the upstream libraries require.

What depends on this: pass 3 (SMPL-X integration), pass 4 (β fitting via A2B and/or optimization), pass 5 (anthropometric verification).

## Approach

**External repos** cloned to `external/` (gitignored — keep our repo small; they're documented as required deps):
- `external/a2b_human_mesh/`
- `external/SMPL-Anthropometry/`

**`src/a2b_adapter.py`:**
- `predict_betas(measurements: dict) -> np.ndarray` — invokes A2B inference and returns a (10,)-shaped β array
- Internal: translate canonical measurement keys + cm units → A2B's expected keys + meter units
- Handle missing measurements with A2B's training-set means (if the repo exposes them) or fall back to warnings + zeros
- `A2B_MEASUREMENT_MAP: dict[str, str]` — explicit mapping, derived from inspecting the repo's source/data files

**`src/anthropometry_adapter.py`:**
- `measure_mesh(vertices: np.ndarray, gender: str = "female") -> dict[str, float]` — wraps `MeasureBody`
- Returns measurements in cm under our canonical key names
- Accepts (10475, 3) SMPL-X vertex arrays

**`scripts/smoke_test_adapters.py`:**
- Calls `predict_betas` on `target_measurements.json` — prints output shape and values
- Generates or loads a synthetic / reference SMPL-X vertex array (10475, 3), calls `measure_mesh`, prints results
- Writes a JSON report to `outputs/adapter_smoke_test.json`

**`passes/pass-2-external-adapters/report.md`** — what we learned from running the code: actual API surfaces, measurement key mappings, units, deviations from the design doc.

## Alternatives considered

1. **Skip adapters, integrate libraries directly in pass 3.** Rejected: that's how pass 3 ends up debugging three things at once. Adapter layer separates "make external libs work" from "make our science work."
2. **Reimplement A2B from scratch.** Rejected: A2B's value is its trained weights. Reimplementing isn't cheaper.
3. **Reimplement SMPL-Anthropometry's measurements in PyTorch now (the differentiable layer Stage 2A needs).** Tempting, but it's a substantial pass on its own (geodesics + cross-section circumferences + autograd). Out of scope here.

## Risks & open questions

- **A2B may pull in incompatible deps.** If it requires a PyTorch version that conflicts with the current install, we'll need a separate venv or pinning. Mitigation: install in a fresh venv if needed.
- **A2B's pretrained weights may be gated.** The repo claims they exist but may require external download. If unreachable: write the adapter against the API anyway, document the blocker.
- **SMPL-Anthropometry may require an actual SMPL-X model to instantiate `MeasureBody`.** If so, full smoke-test deferred to pass 3 (when SMPL-X weights are around) — adapter is still valuable.
- **Either repo may fail to install in this sandbox** (Python 3.11 incompat, GPU-required deps). Mitigation: fall back to source-reading + adapter-as-documentation if execution blocks.
- **A2B's measurement key names may not be cleanly documented.** Plan: inspect `anthro/data/` or equivalent in the repo source.

## Acceptance criteria

- `external/a2b_human_mesh/` and `external/SMPL-Anthropometry/` cloned locally
- `src/a2b_adapter.py` exports `predict_betas(measurements) -> np.ndarray` with an explicit measurement-key map
- `src/anthropometry_adapter.py` exports `measure_mesh(vertices, gender) -> dict[str, float]`
- `scripts/smoke_test_adapters.py` runs and prints results for at least one adapter (both ideal; one acceptable)
- `passes/pass-2-external-adapters/report.md` documents verified APIs and any divergence from the design doc
- `.gitignore` updated to exclude `external/`
