# Pass 3: SMPL-X body with hip + waist mesh corrections

**Status:** v1 — auto-approved by user (feedback round skipped on user request)

## Goal

Produce a real SMPL-X body that hits target measurements within tolerance — including the hip and waist that SMPL-X's 10-β space cannot reach alone — and render it from 8 angles. Replace pass 1's primitive proxy in the pipeline.

## Context

Pass 2's end-to-end smoke test made the hard constraint concrete: SMPL-X female with 10 β has a structural ceiling around 128 cm hip. Our target is 138.7. Worse, the same SVR-clipped β that gets stature exactly right produces a waist 12 cm wider than target. We need two corrections, not one — inflate hip outward by ~15 cm, compress waist inward by ~12 cm — to produce the hourglass our subject actually has.

Three response options were on the table after pass 2:
1. SUPR (different parametric model, wider shape space)
2. Post-process the SMPL-X mesh programmatically
3. Manual Blender sculpt

We're taking option 2 because it's the lowest-effort path that reaches target measurements, doesn't require new academic registration or a new adapter, and produces a mesh whose silhouette we can put in front of Nano Banana to learn whether mesh fidelity is the limiting factor or whether downstream image-gen extrapolation is. SUPR remains the escalation if option 2's rendered mesh looks unnatural enough that Nano Banana mis-interprets it.

What this depends on: SMPL-X weights at `models/smplx/` (pulled from the user's GitHub release in pass 2 follow-up), the `smplx` Python package, the A2B and SMPL-Anthropometry adapters from pass 2, pass 1's render module, trimesh + matplotlib.

What depends on this: pass 4 (Nano Banana integration uses these renders); pass 5+ (decide whether mesh correction is enough or whether SUPR / Blender escalation is needed, based on Nano Banana output).

## Approach

**Starting point.** A2B SVR with β clipped to ±5. Justification from pass 2 data:

| variant | stature err | waist err | hip err | total \|err\| |
| ------- | ----------- | --------- | ------- | ------------ |
| NN raw | -9.04 | +4.46 | -20.58 | 34.08 |
| NN clipped | -6.45 | +19.28 | -11.03 | 36.76 |
| SVR raw | +0.79 | +16.49 | -22.51 | 39.79 |
| **SVR clipped** | **+0.27** | **+11.89** | **-15.18** | **27.34** |

SVR clipped wins on stature (the single measurement we shouldn't compromise) and overall total error. The two large residuals (waist +12, hip −15) are exactly what mesh correction targets.

**`src/smplx_body.py`:**
- `build_smplx_mesh(beta, pose=None, gender="female") -> (trimesh.Trimesh, np.ndarray verts, np.ndarray faces)`
  - Wraps `smplx.create(...)` + forward pass
  - Default pose: relaxed standing — shoulders rotated 15° outward (axis-angle on body_pose indices 15:18 and 16:19)
  - Returns the posed mesh and underlying numpy verts/faces
- `fit_beta(measurements, model_type="svr", clip=5.0) -> np.ndarray` — wraps `a2b_adapter.predict_betas` and clips for sanity

**`src/mesh_correction.py`:**
- `gaussian_radial_deform(verts, center_y, sigma_y, scale_lat, scale_ap, body_facing_axis="+z") -> verts`
  - For each vertex, compute Gaussian weight on vertical distance to center_y
  - In X-Z plane, compute displacement from the centroid of vertices within ~3σ of center_y
  - Scale that displacement by `(1 + weight × (scale - 1))` per axis; lateral (X) vs anterior-posterior (Z) can differ
  - Anterior-posterior anisotropy: vertices with negative Z relative to centroid (posterior) get `scale_ap`; positive Z (anterior) get a milder scale = midpoint between `scale_lat` and `scale_ap`
- `correct_to_target_circumference(verts, faces, gender, measurement_name, target_cm, sigma_y, anisotropy=(1.0, 1.4), max_iters=4) -> verts`
  - Measure current circumference at the upstream-defined plane
  - Compute scale = target / current; refine iteratively (the deformation changes the measured value non-linearly)
  - Returns corrected verts when within 0.5 cm or after `max_iters`

**`scripts/build_corrected_body.py`:**
1. Load `target_measurements.json`
2. Fit β via A2B SVR clipped
3. Build SMPL-X T-pose mesh
4. Measure raw → save `outputs/smplx/verification_raw.json`
5. Apply hip inflation correction (target 138.7, anisotropy=(1.0, 1.4))
6. Apply waist compression correction (target 72.1, anisotropy=(1.0, 1.0) — waists are roughly elliptical-symmetric)
7. Measure corrected → save `outputs/smplx/verification_corrected.json`
8. Apply standing pose
9. Export OBJ to `outputs/smplx/mesh_corrected.obj`
10. Render 8 views via existing `src/render.py` to `outputs/smplx/renders/view_*.png`

**Pose**: relaxed standing. body_pose is 63-dim; only the two shoulder joints get non-zero rotations.

**Renderer**: pass 1's matplotlib renderer, unchanged. ~20k faces vs ~11k in pass 1; expect 2–4× slower, still acceptable for 8 views.

## Alternatives considered

1. **SUPR / STAR.** Right answer for fidelity; wrong as first move. Defer until we have evidence the post-process isn't enough.
2. **Manual Blender sculpt.** Higher fidelity, slower, bespoke. Backstop if programmatic correction looks wrong.
3. **Uniform radial scaling** (no anisotropy). Cleaner code but produces tubular hips — buttocks don't protrude posteriorly. Anisotropy is ~5 extra lines.
4. **T-pose only.** Simpler but per design doc §8 the arms-out T-pose is bad for reference images. Worth the small pose complexity.
5. **Start from NN-clipped** (smallest hip residual, −11). Rejected: stature off by 6.5 cm and waist error is +19 — total correction larger.
6. **Combine multiple A2B outputs** (weighted average). Could blend NN-raw's narrow waist with SVR-clipped's exact stature. Premature; one starting point + corrections is simpler and we can iterate.

## Risks & open questions

- **Anisotropy 1.4 is a guess.** May produce too much posterior protrusion or not enough. Visual inspection of the render is the verification — re-tune if it looks wrong.
- **σ_y choice.** Too large → spills into waist; too small → visible ring of deformation. Starting at σ=6 cm for hip, σ=4 cm for waist; iterate.
- **Waist compression** at 12 cm on a body where waist is currently 84 cm = scale of 0.86. Modest. Self-intersection unlikely.
- **Pose vector indices** may be off for our SMPL-X version. Mitigation: render a T-pose first, then a posed version, eyeball.
- **20k-face matplotlib** may be slow. If wall time becomes annoying, decimate mesh for rendering only.
- **Shoulder breadth** still 11+ cm short of target. Likely measurement-definition mismatch (biacromial vs bideltoid). Not fixing in this pass; flag if rendered shoulders look too narrow.
- **The corrections are local.** Other measurements should not drift, but verify post-correction.
