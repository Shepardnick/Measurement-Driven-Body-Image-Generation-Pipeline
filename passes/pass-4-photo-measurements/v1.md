# Pass 4: Re-derive target measurements from reference photos

**Status:** v1 — auto-approved by user (skip feedback round per ongoing user instruction).

## Goal

Replace `target_measurements.json` with values derived correctly from reference photos using MediaPipe pose detection + body segmentation + proper ellipse-perimeter math, calibrated against user-declared stature (193 cm). The current values were systematically wrong because circumferences were computed as `width × π` — treating the body cross-section as a perfect circle, inflating hip by ~20% over the true elliptical perimeter.

## Context

Pass 3 hit its measurement targets but the rendered body looked cartoonish. Comparing the SMPL-X mesh to the user's reference photos exposed the bug: the photo subject is athletic-curvy (≈ W/H 0.7) and the rendered body is plus-size caricature (W/H 0.52). The mismatch traces to `target_measurements.json` — three independent measurements (hip 138.7, bust 107.2, waist 72.1) all match `width_inches × π × 2.54` to within rounding. Whoever produced these values multiplied 2D pixel widths by π. Real cross-sections are elliptical with depth ≠ width; the true perimeter is much smaller.

This pass rebuilds the measurement targets correctly so pass 3's corrections don't have to inflate the mesh past a reasonable body.

What this depends on: 5 reference photos uploaded to `references/`, MediaPipe (to be installed), declared stature 193 cm as the calibration scale.

What depends on this: pass 3 re-run with the corrected measurements (call it pass 5); all downstream renders and Nano Banana references.

## Approach

**1. Reference photo catalog.** Already in `references/`:
- `front_full.jpg` — clean full-body front view; primary source for widths
- `collage_4panel.jpg` — front / back / side / face composite; side panel is the depth source
- `labeled_reference.jpg` — original labeled image with the (in-image) width/depth annotations; cross-check
- `collage_front_face.jpg`, `collage_dense.jpg` — additional views for cross-validation

**2. `src/photo_measure.py`** with these primitives:
- `detect_pose(image)` → 33 MediaPipe landmarks in normalized image coords + visibility scores
- `segment_body(image)` → boolean mask of body pixels (MediaPipe Selfie Segmentation or rembg fallback)
- `pixels_per_cm(landmarks, image_height_px, declared_height_cm)` — calibration via head-to-ankle pixel distance
- `width_at_landmark(mask, landmark_y_px, expand=4)` — robust horizontal extent of mask near a Y coordinate
- `extract_widths_from_front(image, declared_height_cm)` → dict of widths at shoulder, bust, waist, hip, mid-thigh, knee, calf, ankle
- `extract_depths_from_side(image, declared_height_cm)` → same Y-levels from side view, anterior-posterior extent
- `compute_circumferences(widths_cm, depths_cm)` — Ramanujan ellipse perimeter at each plane

**3. `scripts/measure_from_photos.py`** driver:
- Load front photo, extract widths
- Crop side panel from `collage_4panel.jpg`, extract depths
- Match widths to depths by anatomical landmark
- Compute circumferences via Ramanujan
- Compare to `target_measurements.json` (old vs new side-by-side)
- Write `target_measurements_v2.json`

**4. After this pass:** re-run pass 3's `build_corrected_body.py` against the new measurements (lower hip target, accurate waist/bust). The mesh corrections become small or unnecessary, the rendered body should look like the photo subject.

## Alternatives considered

1. **Single-image SMPL-X fit (CLIFF / PIXIE / PARE / HMR2).** Feedforward 3D body predictors trained to fit SMPL/SMPL-X to a photo silhouette. Higher accuracy in principle. Rejected for v1: setup heavier than MediaPipe + ellipse math, model weights have their own gates, and the photo's AI-generated nature means a feedforward predictor may produce a *different* "subject" than what the photo shows. The MediaPipe path gives transparent measurements anyone can verify with a ruler on the image.
2. **Multi-view SMPL-X fit (SMPLify-X with 4–5 photo views).** Most accurate; days of setup. Escalation path if MediaPipe approach is insufficient.
3. **Manual landmark annotation.** Mark each plane by hand, measure pixels manually. Cheap, transparent, but slow and prone to my own visual estimation bias.
4. **Trust the labeled reference image's in-image numbers** (`Bust: 21.0"`, `Waist depth: 8.3"`, etc.) without re-extracting. Tempting because the numbers exist. Rejected because the labels are partially cut off, units are mixed (inches), and we already know one pipeline produced the bad `target_measurements.json` from related numbers — independent re-extraction is the cross-check.

## Risks & open questions

- **AI-generated photos have inter-frame proportional inconsistency.** The "same subject" in different photos may have slightly different waist-to-hip ratios. Mitigation: median across multiple front views.
- **Bikini bottom rides above the true widest hip line.** Hip widest is typically at trochanter level (just below the bikini waistband); the bikini may obscure or shift this. Mitigation: extract widths from the silhouette mask using a Y-sweep to find the local maximum near hip level, not just at the bikini line.
- **Single side view depth is sensitive to subject lean / camera angle.** Mitigation: report uncertainty if only one side view is usable.
- **193 cm height is itself a declared value, not measured.** If wrong, all absolute measurements scale wrong. Mitigation: report measurements as both absolute AND as height-normalized ratios so the user can sanity-check.
- **MediaPipe install may pull conflicting deps.** Mitigation: try first; fall back to OpenCV + manual landmark detection if it breaks the environment.
- **Some photos have multiple people / occluded poses.** MediaPipe handles single-subject best. Mitigation: use `front_full.jpg` (clean isolated subject) as primary.
