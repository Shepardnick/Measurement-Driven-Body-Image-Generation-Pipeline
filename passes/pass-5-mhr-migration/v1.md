# Pass 5: Migrate from SMPL-X to MHR (Momentum Human Rig)

**Status:** v1 — auto-approved by user (skip feedback round per ongoing instruction)

## Goal

Replace SMPL-X with Meta's MHR as the parametric body source. Validate end-to-end that MHR can be installed in this sandbox, load its default-shape body, render it through our existing 8-view render pipeline. Stretch goal: convert our pass-3 SMPL-X corrected mesh into MHR's shape space using Meta's conversion tools and compare renders side-by-side.

Pass succeeds (v1 acceptance) if a default-shape MHR body renders correctly from the front. Full measurement-driven fitting to our `target_measurements.json` is deferred to pass 6.

## Context

Passes 3 and 4 showed SMPL-X's 10-β PCA shape space cannot represent our subject without entanglement artifacts: pushing β to fit wide hips simultaneously flattens the chest and scoops the upper abdomen. The PCA components are not independent. Mesh correction layered on top fixes circumferences but leaves visible anatomical weirdness.

MHR (Meta, v1.0.0 released Nov 19 2025, paper arXiv:2511.15586) directly addresses this:

- **45 identity parameters** (20 body + 20 head + 5 hands) — 2× SMPL-X for body specifically
- **Non-linear shape model** (MLP-based) — not PCA-entangled
- **Decoupled skeleton + shape** — explicitly inspired by ATLAS, the model designed to fix exactly the entanglement we hit
- **Apache 2.0** — no academic gate
- **Public release** — `curl -OL` works directly (verified: HTTP 200, 198,684,579 bytes)
- **From Meta, actively maintained**
- **Paper reports lower fitting error than SMPL-X especially at extremities** (elbows, knees, shoulders)

Switching the body source while preserving our render pipeline + measurement extraction tooling is the architecturally clean move. `src/render.py` already takes any trimesh; the SMPL-X→render and MHR→render integrations both terminate at the same `trimesh.Trimesh` constructor.

What this depends on: internet access (verified), the existing `src/render.py` (proven), Python 3.11+, PyTorch, pymomentum, trimesh.

What depends on this: pass 6 (build measurement→identity fitting for MHR, replacing the A2B path), pass 7+ (Nano Banana integration using MHR-rendered references).

## Approach

Three stages, each separately committable. Pass v1 ships if stage 1 succeeds; stages 2 and 3 are stretch within the same pass.

### Stage 1 — Install + default-shape smoke test (must)

1. Clone `https://github.com/facebookresearch/MHR.git` to `external/MHR/`
2. Download `assets.zip` from the v1.0.0 release (~190 MB) into `models/mhr/`. Unzip
3. Install dependencies — try pip first (their experimental path, less invasive):
   - `pip install pymomentum-cpu`
   - `pip install mhr`
   - If either fails: install miniconda + pixi, follow their recommended path
   - If both fail: fall back to TorchScript-only path (`models/mhr/assets/mhr_model.pt` + `torch.jit.load(...)`); document the limitation
4. Write `src/mhr_body.py` with `build_mhr_mesh(identity_coeffs=None, model_parameters=None, face_expr_coeffs=None, lod=1, device='cpu') -> trimesh.Trimesh`. All zeros default → default-shape body. CPU device explicit (their demo uses `torch.cuda.FloatTensor`; we need to override).
5. Write `scripts/build_mhr_default.py` — call `build_mhr_mesh()` with all zeros, scale to centimeters (MHR is meters like SMPL-X), render via existing `src/render.py`
6. Outputs: `outputs/mhr/mesh_default.obj`, `outputs/mhr/renders/view_*.png` (8 views, 1024×1024)

### Stage 2 — Identity exploration (stretch)

7. Generate 6 bodies at random identity_coeffs (Gaussian, std=0.8 per their demo): zero, all-positive-1σ, all-negative-1σ, and 3 random samples
8. Render front-only of each at lower resolution (512), to `outputs/mhr/exploration/`
9. Manually inspect; the goal is to see whether MHR's shape space covers a diverse body-type range — verifies the non-linear shape model claim

### Stage 3 — Convert pass-3 SMPL-X corrected mesh → MHR (stretch)

10. Look at `external/MHR/tools/mhr_smpl_conversion/README.md` for the conversion API
11. Feed our `outputs/smplx/mesh_corrected.obj` (pass 3 output, in SMPL-X topology) through the conversion tool
12. Render the converted body
13. Side-by-side comparison with pass-3 SMPL-X render

Caveat: stage 3 converts a SMPL-X-limited mesh into MHR's space. The shape is already constrained by SMPL-X's PCA, so we don't fully exercise MHR's expressivity — the result will look similar to SMPL-X. Pass 6 (measurement-driven MHR fitting) is what actually unlocks the improvement.

## Alternatives considered

1. **Skip the install, use Meta's Sam3D image-fitting tool** (referenced from MHR README). Fits MHR identity from photo input. Could be cleaner than measurement-driven fitting for our case since we have photos. Deferred — Sam3D is its own setup story and pass 5 should be focused.
2. **Build measurement-driven MHR optimizer in this pass.** Most direct path to "MHR body matching our targets." Real effort: writing autograd loss over identity_coeffs against a forward-passed mesh measurement. Out of scope for v1 of pass 5; that's pass 6.
3. **Stay on SMPL-X, fix bust with another correction band.** Already considered, rejected — fundamentally PCA-entangled, every fix exposes another artifact.
4. **TorchScript-only path** as primary install. Simpler but limited to LOD 1, less access to internals. Will use as fallback if pip + pixi both fail.
5. **MakeHuman / DAZ.** Better than SMPL-X but a fundamentally different ecosystem (GUI-driven, OBJ export workflow). Picked MHR over them because MHR keeps us in the CV/parametric track our existing tooling targets, and the Apache+Meta combo is more sustainable than waiting on a hobbyist project.

## Risks & open questions

- **pip path is "experimental"** per their README. If `pymomentum-cpu` or `mhr` fail to install, escalate to pixi (needs conda install first).
- **CPU-only execution** — MHR demo uses `torch.cuda.FloatTensor` directly. Need to either (a) substitute `torch.FloatTensor`, (b) pass `device=torch.device('cpu')` everywhere supported, or (c) accept that the model class itself may need a CPU patch.
- **pymomentum is a real dependency** — Meta's separate library, has its own install gotchas. May conflict with our existing torch version (2.11.0).
- **trimesh ≥ 4.8.3** required by MHR; we have 4.12.2 ✓
- **Topology mismatch with SMPL-Anthropometry adapter.** MHR meshes can't be measured by our existing tool. Pass 5 doesn't claim measurement validation — that's pass 6 with either MHR-native measurement code or the conversion-then-measure path.
- **Asset zip contents unknown.** 190 MB — likely FBX rigs + tensor files. Add gitignore patterns; commit only the inventory, not the assets.
- **CUDA-bound code paths.** Beyond the demo, MHR's pose corrective MLP and forward pass may have CUDA assumptions in the internals. CPU path may be slow or hit unsupported ops.
