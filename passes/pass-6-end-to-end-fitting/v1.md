# Pass 6: End-to-end photo-to-body fitting pipeline

**Status:** v1 — awaiting feedback

## Goal

Replace the ad-hoc per-body workflow with a single-command pipeline: reference photos (or measurements) in → fitted MHR body + 8 view renders out. Build it as a permanent system. Surface MHR's known bust/butt under-fitting as a clean config-driven manual-adjustment layer, not as buried mesh-correction code.

By the end of this pass, the per-body workflow is:

```
edit configs/<body>.json
python scripts/build_body.py configs/<body>.json
```

That's it. No script tweaks, no source edits, no `mesh_correction.py` hacks.

## Context

What pass 5 left us with:
- MHR loads and renders cleanly from any identity_coeffs
- Identity space spans diverse bodies, confirmed empirically
- We have no automated way to find the identity_coeffs that match *our* subject — currently still rendering arbitrary bodies

What MHR's own maintainers tell us (issue #25, Dec 1 2025):
- Single gender-neutral model. No separate male/female variants.
- **"There's no specific control for bust size. Some of the shape parameters will change it, but they'll also change other body parts. You'll have to play around with adjusting some of the parameters manually."**
- This is a known structural limit, not a bug.

What Meta provides as the image-to-MHR pipeline:
- **Sam3D** (`facebookresearch/sam-3d-body`) — fits MHR identity + pose from a single image. Meta's blessed tool for exactly our problem. The MHR README explicitly says "If you want to do Human Motion Recovery with MHR, head to Sam3D." Requires GPU. SAM License (separate from MHR's Apache 2.0).

What we have from earlier passes that's still useful:
- `target_measurements.json` (corrected via pass 4 from photos, W/H 0.62) — gives us a known-good measurement target
- 5 reference photos in `references/` — direct ground truth
- `src/render.py` — works on any trimesh; render pipeline stays
- `src/mhr_body.py` — manual blendshape application, works
- Python 3.12 venv `.venv-mhr/` with MHR + render deps installed

What's missing:
- Identity fitting (no A2B equivalent for MHR; nothing maps measurements or photos to identity_coeffs)
- An entry point — `scripts/build_body.py <config>` doesn't exist
- A configuration layer per body (everything's currently hardcoded paths)
- Manual identity adjustment as a first-class feature
- Cleanup of dead SMPL-X-era code

## Approach

Six stages. Stages 1–4 build the core system; 5 and 6 are integration/cleanup.

### Stage 1 — Fitter interface (`src/body_fitter.py`)

Define the contract that both fitting methods (Sam3D and measurement-optimizer) implement:

```python
def fit_identity_from_photos(photos: list[Path]) -> np.ndarray:    # (45,) float32
def fit_identity_from_measurements(target: dict) -> np.ndarray:   # (45,) float32
def apply_identity_adjustment(base: np.ndarray, deltas: dict[int, float]) -> np.ndarray:
```

Outputs are always a length-45 identity_coeffs vector. Fitting methods are interchangeable downstream.

### Stage 2 — Sam3D integration (primary fitting path)

- Clone `facebookresearch/sam-3d-body` into `external/sam-3d-body/`
- Install its deps in `.venv-mhr` (same Python 3.12 environment)
- Download model checkpoints to `models/sam-3d-body/`
- Wrap inference behind `fit_identity_from_photos(photos)`
- Handle GPU absence gracefully: try CUDA → CPU → raise informative error and fall back

**Honest expectation:** Sam3D will probably fit identity better than our autograd measurement optimizer because it uses the full image signal (silhouette + texture cues + facial features for sex characteristics), not just circumference numbers. But bust/butt under-fit will probably persist — that's the model's limit.

### Stage 3 — Measurement-driven optimizer (fallback fitting path)

When Sam3D isn't available (no GPU, no weights, install failure, AI photos out of distribution):

- PyTorch autograd loop over a 45-dim `nn.Parameter` for identity_coeffs
- Forward pass: existing `build_mhr_mesh()` (einsum-based, differentiable)
- Differentiable measurements on the MHR mesh:
  - **Stature** = max(Y) − min(Y)
  - **Plane-cut circumferences** (waist, hip, bust): plane intersection then perimeter sum, implemented in PyTorch
  - **Lateral widths** (shoulder breadth, hip width) from specific landmark vertex indices
- Loss = weighted MSE between predicted and target measurements
- Adam optimizer, gentle regularization on identity_coeffs magnitude

Landmark vertex indices for MHR's 18,439-vert mesh need to be identified once and committed to `data/mhr_landmarks.json`. Source: visual inspection + cross-reference with the FBX rig's joint positions.

### Stage 4 — Per-body configuration (`configs/<body>.json`)

```json
{
  "name": "subject_a",
  "source": "photos",
  "photos": ["references/front_full.jpg", "references/collage_4panel.jpg"],
  "measurements": "target_measurements.json",
  "identity_adjustment": {
    "comment": "Manual deltas applied AFTER fitting, per Meta's recommended workflow for bust/butt tuning",
    "deltas": {}
  },
  "pose": {
    "kind": "relaxed_standing",
    "shoulder_drop_deg": 70.0
  },
  "lod": 1,
  "render": {
    "resolution": 1024,
    "angles_deg": [0, 45, 90, 135, 180, 225, 270, 315]
  }
}
```

Both `photos` and `measurements` can be present — `source` decides which is primary, the other is used for verification. `identity_adjustment.deltas` is an integer → float map: which identity components to nudge after fitting, per Meta's "play with parameters manually" guidance.

The adjustment lives in version control. Tweaking the body is editing this file, not editing code.

### Stage 5 — Single entry point (`scripts/build_body.py`)

```bash
.venv-mhr/bin/python scripts/build_body.py configs/subject_a.json
```

Pipeline:
1. Load config
2. Fit identity via `body_fitter.fit_*` per `source`
3. Apply `identity_adjustment.deltas`
4. Build pose vector per `pose.kind`
5. Build mesh via `build_mhr_mesh(identity_coeffs, ...)`
6. Render 8 views via existing `src/render.py`
7. Compute verification: re-measure mesh, compare to `measurements`, write report
8. Write everything to `outputs/<name>/`

### Stage 6 — Legacy cleanup

Delete files that the SMPL-X era left behind. They're replaced and confusing:

- `src/anthropometry_adapter.py`
- `src/mesh_correction.py`
- `src/smplx_body.py`

Keep:

Document the deletion in `passes/pass-6-end-to-end-fitting/report.md` so the audit trail is clear.

## Alternatives considered

1. **Skip Sam3D, autograd-optimizer only.** No new deps, no GPU, no license complications. Discards the richer signal in photos. Rejected as *primary* but kept as fallback — Meta clearly believes image fitting is the right path or they wouldn't have built Sam3D.

2. **Skip MHR, use MakeHuman.** Sliders are explicit and named, breast size is its own slider. Different ecosystem; we'd discard the pass-5 work. Rejected because we just invested in MHR and the MHR identity space already covers our subject (pass 5 stage 2's all_plus_1 result proves this).

3. **Add a bust-correction mesh-deformation band like we had in SMPL-X.** Explicit patch. User-instructed against. Rejected.

4. **Skip 3D entirely and feed photos to Nano Banana directly.** Still on the table as the actual cheapest test for the project's *real* goal. Not what this pass is about — that's a parallel investigation. Could be run alongside pass 6 by anyone; doesn't block.

5. **Use Sam3D's pose output but ignore its identity output.** Possibly cleaner because pose is well-defined and identity is the under-fit-prone part. Not chosen because Sam3D's identity is exactly what we need; if it under-fits we adjust via `identity_adjustment.deltas`.

6. **Train a custom bust/butt blendshape on top of MHR.** Weeks of work; per-body. Overkill.

## Risks & open questions

- **GPU absent in this sandbox.** Sam3D may not run, or may run slowly on CPU. The fallback to the autograd-optimizer path is critical. May need to document "fit Sam3D locally on your machine, upload identity_coeffs as JSON" as a workflow.

- **SAM License.** Different from Apache 2.0. Need to verify acceptable use before downloading checkpoints. Likely fine for research/personal but worth checking.

- **Hugging Face gating.** Sam3D checkpoints are on HF. May require accepting model terms before download. Document the user-action step if so.

- **AI photo distribution shift.** Sam3D trained on real photos. Our reference photos are AI-generated. Fit quality could degrade. Worth checking the result before declaring success.

- **MHR landmark vertex indices unknown.** For the autograd-measurement fallback we need to know which vertices are shoulder, hip, knee, etc. Not documented; have to discover by visualizing default mesh + joint positions. ~1 hour of work.

- **Differentiable plane-cut measurement** is non-trivial in PyTorch. The plane-mesh intersection needs to produce a polygon whose perimeter can be summed. Workable but a real chunk of code.

- **Persistent bust/butt under-fit.** Per Meta dev, no clean automated fix. The `identity_adjustment.deltas` config knob is honest about this. Users adjust by hand if needed.

- **Sam3D + matplotlib may not coexist cleanly in the same venv.** Sam3D likely brings its own torch version, transformers, etc. Could break our existing setup. Maybe split into a separate venv (`.venv-sam3d`) and use file-based handoff (Sam3D writes identity.json, build_body.py reads it).

## Acceptance criteria

- `scripts/build_body.py configs/subject_a.json` runs end-to-end without errors
- Output: `outputs/subject_a/mesh.obj`, `outputs/subject_a/renders/view_*.png` (8 views, 1024×1024), `outputs/subject_a/verification.json`, `outputs/subject_a/identity.json`
- At least one of two fitting paths (Sam3D or autograd-optimizer) works on this environment
- `identity_adjustment.deltas` in the config takes effect — same fit, different deltas produces visibly different bodies
- `verification.json` reports residuals between target measurements and as-measured-on-rendered-mesh, with named per-measurement errors
- Front render visually plausible: head/torso/arms/hips in proportion, no narrow-shoulder-caricature, no scooped-abdomen artifact
- Legacy SMPL-X-era files deleted (stage 6)
- `passes/pass-6-end-to-end-fitting/report.md` documents what got cleaned up and what fit method was used per body

## Out of scope

- Photo-realistic rendering (matplotlib stays for now; pyrender/Blender upgrade is later)
- Nano Banana integration (separate pass)
- Pose authoring beyond a hardcoded relaxed-standing variant
- Hand pose refinement
- Face identity / expression
- Training custom blendshapes on MHR
- Multi-subject pipelines / batch processing
