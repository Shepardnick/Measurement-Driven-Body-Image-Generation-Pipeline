# Pass 6 v2: End-to-end photo/measurement-to-body pipeline

**Status:** v2 — supersedes v1 (Sam3D path dropped per user direction)

## Goal

Replace the ad-hoc per-body workflow with a single-command, config-driven pipeline. Web-friendly (no GPU). Modifiable (edit one JSON file, never source code). High-quality output (real lit/shaded renders, not matplotlib flat polygons).

End state:

```bash
edit configs/subject_a.json
.venv-mhr/bin/python scripts/build_body.py configs/subject_a.json
# → outputs/subject_a/{mesh.obj, renders/view_*.png (smooth shaded), verification.json, identity.json}
```

That's it. No script edits. No `mesh_correction.py` hacks.

## Context

What changed from v1:
- **Sam3D dropped.** Requires GPU complications and a separate venv. Marginal benefit over a CPU autograd-optimizer that uses the measurements we already extracted from photos in pass 4. User wants this web-based.
- **Renderer upgraded.** Pass 1-5 used matplotlib's flat-shaded 3D backend — fine for "is the body recognizable" verification, terrible for actual Nano Banana references. v2 uses pyrender (primary) or Open3D (fallback) for smooth-shaded, lit, anti-aliased renders. Big visual jump on the same CPU.

Sandbox verified specs: 4-core Xeon @ 2.80GHz, 15 GB RAM, no GPU. All operations below fit comfortably:

- MHR forward pass (einsum on a (45, 18439, 3) tensor): <100 ms
- Autograd-optimizer over 45 identity_coeffs to 100 iterations: ~10-30 s
- pyrender of an 18k-vert mesh from one view: ~1-3 s
- Full 8-view render of one body: ~10-25 s

What we already have:
- MHR loads cleanly in `.venv-mhr` (pass 5)
- `src/mhr_body.py` builds a trimesh from identity_coeffs
- `target_measurements.json` (pass 4) with realistic numbers
- 5 reference photos for verification

What's missing:
- Identity fitting — no automated way to find the identity_coeffs that match our subject
- A single entry point
- A renderer that doesn't look like 1980s graphics
- Plugin architecture so the body source is swappable (MHR fit vs OBJ from MakeHuman/Blender/wherever)
- Cleanup of dead SMPL-X-era code

## Approach

Phases, each with its own commit, so individual failures don't lose other work.

### Phase A — Renderer upgrade (`src/render_quality.py`)

- Try pyrender install in `.venv-mhr` (Python 3.12 should resolve the 3.11 setuptools issue)
- If pyrender works: `render_views_quality(mesh, output_dir, ...)` using pyrender's OffscreenRenderer with PBR skin material, 3-point softbox lighting, anti-aliased
- If pyrender install fails: fall back to Open3D headless renderer with similar settings
- If both fail: keep matplotlib but document the failure clearly
- Material defaults: skin-tone diffuse (~210, 180, 160), light subsurface scattering if supported, low roughness, no metallic
- Lighting: key + fill from front-upper-left and front-upper-right, soft rim from behind
- White background; mesh centered vertically
- Output: same `view_*.png` interface as current `src/render.py` so downstream code doesn't care

### Phase B — Body fitting (`src/body_fitter.py`)

Define a uniform interface:

```python
def fit_identity_from_measurements(target: dict, init: np.ndarray | None = None) -> tuple[np.ndarray, dict]
def load_identity_from_obj(obj_path: Path) -> tuple[np.ndarray | None, trimesh.Trimesh]  # for OBJ source: skip fitting
def apply_identity_adjustment(base: np.ndarray, deltas: dict[int, float]) -> np.ndarray
```

**Autograd optimizer** for `fit_identity_from_measurements`:
- `identity_coeffs = torch.nn.Parameter(torch.zeros(45))` (or init from input)
- Forward: build MHR mesh via the existing einsum path
- Differentiable measurements via landmark-vertex distance:
  - Stature = `max_y(verts) - min_y(verts)` (soft-max / soft-min for differentiability, or use known top/bottom indices)
  - Shoulder breadth = distance between shoulder-acromion landmark vertex pair
  - Hip width = distance between widest-hip-lateral vertex pair  
  - Bust circumference (approximate) = perimeter through a fixed sequence of pre-identified bust-line vertex indices
  - Waist circumference = same, waist-line indices
  - Hip circumference = same, hip-line indices
- Landmark vertex IDs identified ONCE by inspecting the default mesh: find top-Y vertex (head crown), bottom-Y (feet), widest-X at a given Y (acromion at shoulder Y, trochanter at hip Y), 16-32 vertices at each circumference plane found by Y-band + sort-by-angle-around-centroid
- Loss = weighted MSE; stature gets highest weight (it sets scale), then waist+hip+bust, then limbs
- Adam optimizer, lr=0.05, ~150 iterations
- Light L2 regularization on identity_coeffs to discourage drifting toward the rails

**`load_identity_from_obj`** for when source is "obj":
- Just load the OBJ via trimesh. Identity is `None` (we don't reverse-fit). The mesh IS the body; we render it directly.
- Lets MakeHuman / Blender / hand-sculpted bodies enter the pipeline as first-class options.

**`apply_identity_adjustment`** adds the deltas to the fitted identity. This is where Meta's "tweak manually" advice lives — exposed as a JSON config field, not a code hack.

### Phase C — Config + CLI (`configs/`, `scripts/build_body.py`)

`configs/subject_a.json` schema:

```json
{
  "name": "subject_a",
  "source": "measurements",
  "obj_path": null,
  "measurements_path": "target_measurements.json",
  "photos": ["references/front_full.jpg"],
  "identity_adjustment": {
    "comment": "Per-component deltas added after fit. Meta's recommended way to dial in bust/butt manually.",
    "deltas": {}
  },
  "pose": {"kind": "tpose"},
  "lod": 1,
  "render": {
    "backend": "auto",
    "resolution": 1024,
    "angles_deg": [0, 45, 90, 135, 180, 225, 270, 315]
  }
}
```

`scripts/build_body.py <config>`:
1. Load config
2. Dispatch on `source`: measurements → fit, obj → load
3. Apply `identity_adjustment.deltas`
4. Build mesh
5. Render via Phase A renderer
6. Compute verification: re-measure mesh, compare to target, write report
7. Write `outputs/<name>/{mesh.obj, renders/, identity.json, verification.json}`

## Alternatives considered

1. **Keep matplotlib renderer.** Simplest. Renders look like 1980s graphics. Rejected — visual quality matters for Nano Banana references and for the user's own iteration loop.

2. **Blender CLI as renderer.** Higher quality possible (Cycles raytracing). 30-120s/render at our CPU; 4-16 min/body — too slow for iteration. Eevee rasterizer would be fast but more install/script complexity than pyrender. Defer to a later pass if needed.

3. **Sam3D for photo-driven identity.** GPU-bound. User explicitly wants web-based simplicity. v1 included it; v2 drops it. Can be added later as an alternative `source: "photos_via_sam3d"`.

4. **Hand-tune identity_coeffs only (no optimizer).** Simplest. Forces user to learn what each of 45 anonymous components does. Tedious. Optimizer is cheap to build and gets us 90% there.

5. **Differentiable plane-cut perimeter measurement.** More principled than landmark-vertex distances. Significantly more code (plane-mesh intersection in PyTorch). Landmark approach is simpler and adequate for the optimizer's purpose. If results are visibly off, we can upgrade.

6. **Pyrender + clothing.** Adding bikini geometry would make renders more like the source photos. Out of scope; one thing at a time.

## Risks & open questions

- **Pyrender install in Python 3.12 venv** might still fail. Fallback: Open3D headless. Worst case: keep matplotlib and add Blender in a later pass.

- **Landmark vertex identification on MHR's mesh** requires inspection. The default-mesh-based heuristics (top-Y, bottom-Y, widest-X-at-Y-fraction) should give correct landmarks because the mean shape is a real human. But for extreme identity_coeffs, the landmarks "move with the body" via blendshape deformation, which is what we want — the optimizer tracks them correctly.

- **Differentiable stature measurement.** `max(verts.y) - min(verts.y)` isn't differentiable through `max`/`min` selecting different vertices for different parameters. Workaround: identify head-crown and floor-foot vertex indices once on the default mesh; use those vertex Y-values directly. Smooth gradient.

- **Bust still under-fits.** Will persist. The `identity_adjustment.deltas` field is the manual override. After running the optimizer, compare rendered bust to photo; if under, add positive deltas to components empirically known to grow bust (likely shape_0..shape_4 from pass-5 evidence that `all_plus_1` produced curves).

- **MakeHuman OBJ path** is untested in this pipeline. The OBJ loader works for any tri-mesh; the renderer doesn't care about source; verification might fail because MakeHuman OBJs have different vertex topology than MHR (no landmark indices). Mitigation: skip verification when `source: "obj"`, or compute verification from the rendered front image via the pass-4 photo_measure pipeline.

- **Disk pressure.** Already at 81% used (mostly torch + assets). Phase A install adds maybe 100 MB; should be fine.

- **`source: "photos"`** is not in v2 (would need Sam3D). The config schema includes the `photos` field for future use and for verification (re-measure rendered output against photo extraction); no fitting path consumes it directly yet.

## Acceptance criteria

- `.venv-mhr/bin/python scripts/build_body.py configs/subject_a.json` runs end-to-end
- 8 PNG renders written to `outputs/subject_a/renders/`, **smooth-shaded with visible lighting / shadows** (clear visual upgrade over matplotlib output)
- `outputs/subject_a/verification.json` shows mesh-measured stature within ±2 cm, W/H ratio within 0.05 of target
- `outputs/subject_a/identity.json` is the actual 45-dim coefficient vector — readable and re-usable
- Editing `configs/subject_a.json::identity_adjustment.deltas` and re-running produces visibly different bodies (proves the manual-tuning loop works without code edits)
- `source: "obj"` path works: drop in any tri-mesh OBJ, get renders
- SMPL-X-era source files deleted (Phase D)
- `passes/pass-6-end-to-end-fitting/report.md` written
- Pipeline survives a fresh-clone test (in principle — not actually re-cloning this pass)
