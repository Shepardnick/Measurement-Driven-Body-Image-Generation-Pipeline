# Pass 7: Migrate body source to CharMorph (named-morph parametric body)

**Status:** v1 — auto-approved by user, executing immediately

## Goal

Replace MHR's 45-dim anonymous PCA identity space with CharMorph's 60+ named, semantic body morphs (`Torso_BreastTone`, `Abdomen_Tone`, `Pelvis_GluteusMass`, etc.). End-state: `configs/<body>.json` accepts explicit named morph values; pipeline applies them to the MB-Lab female base mesh; the existing pyrender pipeline renders the result with no other changes. Archive MHR-era code to `legacy/mhr/`.

## Context

After 6 passes the picture is clear: MHR's identity-space mean produces a soft/average body. Meta's own dev confirmed in issue #25 that bust and glute size aren't controllable independently — shape components are entangled in the PCA. Across all 7 LODs the body geometry is the same smooth averaged surface; muscle definition isn't anywhere in MHR's mesh, only in identity-coefficient directions we can't isolate.

CharMorph (Upliner/CharMorph + CharMorph-db, GPL-3.0, MB-Lab successor, active development 2025) ships explicit named morphs for the exact controls we need. Inspected directly in the cloned repo:

- 60+ named body morphs verified in the female base, including `Torso_BreastMass`, `Torso_BreastTone`, `Pelvis_GluteusMass`, `Pelvis_GluteusSize`, `Pelvis_GluteusTone`, `Abdomen_Tone`, `Torso_Tone`, `Legs_UpperlegsTone`, `Legs_LowerlegsTone`, `Arms_UpperarmTone`, `Arms_ForearmTone`, `Stomach_LocalFat`, `Stomach_Volume`, `Waist_Size`, `Shoulders_SizeX`, `Torso_Vshape`, etc.
- Pre-built archetypes including `type_fitness_model.json`, `type_athletic.json`, `type_hourglass01/02.json`, `type_ideal_fashion.json`, `type_ideal_shapely.json`, `type_extreme_bodybuilder.json` — and ethnic variants per archetype.
- 18,210-vertex quad mesh (~2× MHR LOD 1 effective resolution after triangulation).
- Data format already in numpy: faces.npy + L1/<Ethnicity>.npy (full-vertex offsets) + L2_packed/__main__.npz (packed sparse morphs). No proprietary format barrier.

What's verified working: Blender 4.0.2 installed via apt, `blender --background --python-expr "..."` runs cleanly. CharMorph and CharMorph-db cloned to `external/`.

What's missing for runtime: the base mesh sits inside `char.blend` (Blender binary). One-shot extraction via headless Blender to a `.npz` of vertices, then pure-Python at runtime — no Blender dependency for the actual body builds.

## Approach

Six stages.

### Stage 1 — Verify and document the data format
- `external/CharMorph-db/characters/mb_female/faces.npy`: (17288, 4) quad faces — triangulate before trimesh.
- `morphs/L1/<Ethnicity>.npy`: (18210, 3) full-vertex offset from base for ethnic L1 shape.
- `morphs/L2_packed/__main__.npz`: keys `names` (null-separated UTF-8 packed in uint8), `cnt` (per-morph count), `idx` (concatenated vertex indices), `delta` (concatenated 3D offsets). Decode per CharMorph's `lib/utils.py::np_names` and `lib/morphs.py` slice-by-cumsum pattern.
- `presets/<archetype>.json`: dict `{"structural": {"<MorphName>": value, ...}}`.

### Stage 2 — One-shot base-mesh extraction (`scripts/extract_charmorph_base.py`)

Runs once, under headless Blender:
```
blender --background --python scripts/extract_charmorph_base.py
```
Opens `char.blend`, locates the base mesh object, exports its vertices (18210, 3) to `data/charmorph_female_base.npz`. Faces come from the existing `faces.npy`.

### Stage 3 — Pure-Python adapter (`src/charmorph_body.py`)

API:
```python
build_charmorph_body(
    morph_values: dict[str, float],
    ethnicity_l1: str = "Caucasian",
    triangulate: bool = True,
) -> trimesh.Trimesh
```

Internal flow:
1. Load base vertices from `data/charmorph_female_base.npz` (cached).
2. Apply L1 ethnic base: `verts += L1_offsets[<ethnicity>]`.
3. Load L2 packed morph bundle (cached): build a name → (idx_slice, delta_slice) lookup once.
4. For each named morph in `morph_values`, apply `verts[idx] += delta * value`.
5. Triangulate quads → tris (each quad i,j,k,l becomes two tris i,j,k and i,k,l).
6. Return `trimesh.Trimesh(vertices=verts, faces=tris, process=False)`.

Helper: `load_preset(name: str) -> dict[str, float]` reads `presets/<name>.json` and returns the `structural` dict.

### Stage 4 — Wire into `build_body.py`

New config schema for `source: "charmorph"`:
```json
{
  "name": "subject_a",
  "source": "charmorph",
  "charmorph": {
    "character": "mb_female",
    "ethnicity_l1": "Caucasian",
    "preset": "type_fitness_model",
    "morph_overrides": {
      "Torso_BreastTone": 1.0,
      "Pelvis_GluteusTone": 0.95,
      "Abdomen_Tone": 1.0
    }
  },
  "render": {...}
}
```
Preset is the starting point; `morph_overrides` are applied on top (the explicit no-patches manual-tuning knob, replacing identity_adjustment.deltas with semantically named keys).

`build_body.py` dispatches on `source`:
- `"charmorph"` → preset load + overrides → `build_charmorph_body` → render
- `"obj"` → as before
- `"measurements"` (MHR) → kept for now, marked deprecated

- `src/body_fitter.py` → `legacy/mhr/body_fitter.py`

- `scripts/explore_mhr_identity.py` → `legacy/mhr/explore_mhr_identity.py`

`build_body.py` updated to remove the `source: "measurements"` MHR path. Old `outputs/mhr/`, `outputs/mhr_fitted/`, `outputs/subject_a/` (the MHR-fit version) preserved as historical record.

### Stage 6 — Validate end-to-end

Build `configs/subject_a_charmorph.json` using `type_fitness_model` preset + small manual overrides. Run `scripts/build_body.py configs/subject_a_charmorph.json`. Render. Compare to the MHR subject_a render. Confirm the body looks like an actual fitness female (visible muscle tone, defined glutes, perky bust shape) rather than soft-average.

## Alternatives considered

1. **Run CharMorph as a Blender add-on at runtime.** Heavier dep, slower, CharMorph's TODO explicitly mentions context-handling issues. Rejected; one-shot extraction + pure Python is cleaner.
2. **MakeHuman / MPFB.** Same lineage of morphs; CharMorph is the more modern fork with better-organized data. CharMorph-db includes the MB-Lab presets we care about already.
3. **DAZ Genesis 9 via Diffeomorphic.** Was the alternative I researched. Free starter has limited body morphs; the good ones (Muscularity, etc.) are paid. User vetoed for cost reasons.
4. **Keep MHR + try harder.** Component sweep, identity_adjustment.deltas tuning — we tried; the entanglement makes the body soft regardless. CharMorph's named morphs sidestep the structural issue.
5. **Skip 3D entirely and feed photos to Nano Banana.** Still on the table as a parallel investigation. Not what this pass is.

## Risks & open questions

- **`char.blend` Blender-version compatibility.** CharMorph data was authored in Blender 3.x. Blender 4.0.2 should open it cleanly (forward-compatible), but we'll verify in stage 2.
- **Base mesh object name** inside `char.blend` — likely something like `MBLab_human_female` or similar. Stage 2 script will list all objects and pick the right one heuristically (largest mesh, or by name match).
- **Quad→tri triangulation choice** doesn't matter visually but affects vertex correspondence to MB-Lab's expected topology. Use the consistent (i,j,k) + (i,k,l) split.
- **Morph deltas at "value=1" may be extreme.** MB-Lab convention: most morphs are in the 0–1 range where 1 is the artist's "fully on" value, not a generic σ. Presets use values like 0.4994 etc. — these are tuned. So default scale should be fine; the morph values in presets are absolute targets, not multipliers on σ.
- **Mesh has gender-specific features baked in.** This is `mb_female` — already female-presenting at zero coeffs. Different from MHR's unisex mean. Good for us; less optimizer work.
- **Hair, eyes, lips** still missing — CharMorph supports them but we're scoped to body for this pass per user direction.
- **Disk:** Blender 4.0.2 install added ~300 MB. CharMorph + CharMorph-db total ~150 MB. Fits within current ~7 GB free.
- **License:** CharMorph is GPL-3.0. Our outputs (renders, meshes) are not derivatives of CharMorph code. Importing GPL data through GPL plugin and producing outputs is generally permissive for personal use; commercial use needs care.
