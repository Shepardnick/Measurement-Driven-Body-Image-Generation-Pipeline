# Pass 8: Granular morph catalog + autograd measurement fitter (+ skin texture)

**Status:** v1 — auto-approved by user, executing

## Goal

Three deliverables, ranked by importance:

1. **Accurate measurement-driven fitting.** A PyTorch autograd optimizer over CharMorph's named morphs that hits target measurements (stature, bust, waist, hip, shoulder breadth) within ±0.5 cm. Built on the same machinery that worked for MHR in pass 6.
2. **Complete morph catalog.** Every CharMorph morph exposed and documented — JSON for programmatic access, summary grouped by anatomical region for humans. Easy to drop into a config.
3. **Skin texture support (best-effort).** If CharMorph ships diffuse skin textures + UVs, surface them through the pyrender material in `render_quality.py`. Stretch goal; pass succeeds without it.

End state config gets a new `fit_to_measurements` flag plus an `optimize_morphs` list and a per-morph `morph_values` block:

```json
{
  "source": "charmorph",
  "charmorph": {
    "preset": "type_ideal_shapely",
    "fit_to_measurements": true,
    "measurements_path": "target_measurements.json",
    "optimize_morphs": ["body"],
    "morph_values": {
      "Torso_BreastMass": 0.4,
      "Torso_BreastTone": 0.9,
      "Pelvis_GluteusMass": 0.55,
      ...
    }
  }
}
```

`morph_values` is the manual layer (overrides preset). `fit_to_measurements: true` then runs the optimizer to refine those values against the target measurements, keeping morphs not in `optimize_morphs` fixed.

## Context

Pass 7 produced CharMorph bodies that look genuinely good but only hit measurements within ~5–10 cm because we set morph values by eye. The user wants accuracy comparable to MHR's pass-6 fit (±0.5 cm) but with CharMorph's anatomical quality.

CharMorph's morphs are inherently differentiable: vertices = base + Σ value × delta. The combo morphs add a `max(v_i · sign_i, 0)` clamp at each corner — non-smooth at corner boundaries, but the gradient path through positive-region values is clean. Parameterizing the optimizer over the original slider names (not the corner-storage names) keeps the clamp non-differentiability hidden behind the forward pass.

Compared to MHR's optimizer:
- MHR fit anonymous PCA components → caricature risk. CharMorph fits semantically named morphs → realistic regions stay realistic.
- MHR landmarks were derived heuristically on the 18439-vert MHR mesh. CharMorph's mesh is 18210 verts, different topology. New landmark derivation needed.

## Approach

Six stages, each independently committable.

### Stage 1 — Generate morph catalog

`scripts/build_morph_catalog.py`:
- For every stored morph name (in `L2_packed/__main__.npz` + ethnic packs), parse:
  - `<Part>_<DimA-DimB>_<min|max>-<min|max>` → compound slider pair (`<Part>_<DimA>`, `<Part>_<DimB>`)
  - `<Part>_<Slider>_<min|max>` → 1D slider `<Part>_<Slider>`
- Group by region prefix (Torso, Pelvis, Legs, Arms, Waist, Abdomen, Shoulders, Neck, Head, Cheeks, Chin, Ears, Eyes, Mouth, Nose, Forehead, Hands, Feet, Body).
- Tag "measurement-relevant" sliders (body + limb + neck + shoulders) vs "cosmetic only" (face/eye/mouth detail).
- Write `data/charmorph_morph_catalog.json` keyed by slider name.
- Write a human-readable summary into `passes/pass-8-morph-catalog-and-fitter/morph_catalog.md`.

### Stage 2 — CharMorph landmark vertex rings

`scripts/build_charmorph_landmarks.py`:
- Load default `mb_female` mesh from `data/charmorph_female_base.npz`.
- Use the same convex-hull-band heuristic that worked for MHR:
  - Top of head: max-Y vertex on midline
  - Feet: two min-Y clusters
  - Shoulder pair: extreme |X| at ~84% stature
  - Hip-widest pair: extreme |X| at ~50% stature
  - Bust/waist/hip rings: 2D convex hull of vertices in a thin Y-band, sorted by angle
- Write `data/charmorph_landmarks.json` (vertex indices, sliced).

### Stage 3 — Differentiable measurement layer

`src/charmorph_fitter.py::measure_mesh_torch(verts, landmarks)`:
- Stature = `verts[head_top, 1] - mean(verts[foot_idxs, 1])`
- Shoulder breadth = `||verts[L_shoulder] - verts[R_shoulder]||`
- Hip width = `||verts[L_hip] - verts[R_hip]||`
- Bust/waist/hip = ring perimeter = `Σ ||verts[ring[i+1]] - verts[ring[i]]||`

All differentiable through `verts`, and `verts` is differentiable through morph values via the einsum + combo-corner forward pass.

### Stage 4 — Autograd optimizer

`src/charmorph_fitter.py::fit_charmorph_morphs(target, init, optimize_keys)`:
- Parameter: `torch.nn.Parameter` vector indexed by morph names in `optimize_keys`.
- Initial values: from `init` dict (preset + manual overrides).
- Bounds: clamp via `torch.clamp(params, 0.0, 1.0)` inside forward pass (or use sigmoid reparameterization for smooth bounds).
- Forward: apply all morphs (fixed + optimized) → mesh → measurements.
- Loss: weighted MSE (stature highest weight; circumferences medium; shoulder lower since shoulder definition is fuzzy).
- Regularization: `λ × ||params - init||²` to stay near the artistic preset.
- Optimizer: Adam, lr ~0.03, 200–400 iterations.
- Returns: final `dict[str, float]` of morph values, plus residuals report.

### Stage 5 — Wire into `build_body.py`

Extend the `charmorph` source branch:

```python
def _build_charmorph(config):
    cm = config["charmorph"]
    # Layer 1: preset
    values = load_preset(cm["preset"]) if cm.get("preset") else {}
    # Layer 2: manual morph_values
    values.update(cm.get("morph_values") or {})
    # Layer 3: optional fit
    if cm.get("fit_to_measurements"):
        target = load_measurements(cm["measurements_path"])
        optimize_keys = expand_optimize_groups(cm.get("optimize_morphs", ["body"]))
        values = fit_charmorph_morphs(target, init=values, optimize_keys=optimize_keys)
    mesh = build_charmorph_body(values, ...)
    return mesh, {"final_morph_values": values}
```

`expand_optimize_groups("body")` expands to a sensible default set of body-region morphs from the catalog.

## Alternatives considered

1. **CMA-ES / gradient-free** instead of autograd. More robust to the `max(·, 0)` non-smoothness in combo morphs but 10× more iterations. Autograd-with-parameterization-trick is faster and still robust.
2. **Coordinate descent**: optimize one morph at a time. Misses interactions. Rejected.
3. **Linear analytical inversion** (Jacobian inversion at preset point). Fast but assumes linearity. CharMorph combo morphs are bilinear, so this would be wrong at non-zero combo values.
4. **Skip the catalog and just expose names in errors.** Worse UX. Rejected.

## Risks & open questions

- **Combo-morph clamp non-smoothness.** When two paired morphs satisfy `m * sign_m + t * sign_t = 0`, the gradient w.r.t. either has a kink. Mitigation: in practice optimizer doesn't get stuck exactly at the corner; if it does, small noise perturbation breaks the tie. Verify on test.
- **Optimizer might push toward unrealistic morph combinations** that match measurements but look anatomically wrong. Mitigation: regularize toward the preset; bound values to [0, 1].
- **Combo morphs apply to a stem like `Pelvis_GluteusMass-GluteusTone`**, requiring both slider values be parameterized together. Parameter mapping needs to handle this — if the user puts only `Pelvis_GluteusMass` in optimize_keys, we still need to track the value of `Pelvis_GluteusTone` (it stays at preset or 0). Solved by always parameterizing both members of a combo pair if either is in optimize_keys.
- **Texture extraction needs UV coords.** Blender headless can output them as a UV layer per vertex. One-shot script; adds ~10 min of work.
- **Skin material in pyrender** can do baseColorTexture but no SSS. Going to look more "doll" than "skin" without subsurface scattering. Acceptable; full PBR skin is a separate engineering project.

## Acceptance criteria

- `data/charmorph_morph_catalog.json` exists with ≥60 named sliders, grouped by region, tagged measurement-relevant where applicable.
- `passes/pass-8-morph-catalog-and-fitter/morph_catalog.md` is human-readable.
- `data/charmorph_landmarks.json` has stature, shoulder, hip, bust/waist/hip-ring indices.
- `src/charmorph_fitter.py` exposes `fit_charmorph_morphs(target, init, optimize_keys) -> (morph_values, residuals)`.
- `build_body.py` accepts `fit_to_measurements: true` in a `charmorph` config and runs the optimizer.
- End-to-end on `target_measurements.json` (stature 193.04, bust 104.03, waist 73.58, hip 117.87): final residuals ≤ ±0.5 cm on stature/bust/waist/hip.
- Front render of fitted body still looks anatomically right (visible breasts/glutes/waist, no caricature).
- Skin texture applied if feasible; if not, documented as deferred.
