# Pass 9: Skin texture + bright global lighting + matched body render

**Status:** v1 — auto-approved, executing.

## Goal

Three things, in order:

1. **Apply CharMorph's authored skin texture** (`mb_female/textures/albedo.png`, 2048² RGBA diffuse) to the rendered body via pyrender's `MetallicRoughnessMaterial.baseColorTexture`. Requires one-shot Blender extraction of UVs to match our triangulated topology.
2. **Reconfigure lighting for bright, even global illumination.** High ambient + balanced key/fill (no dominant key), reduce or kill the rim light. The user wants no harsh contrast shadows that hide problems — flatter, more diagnostic, more like overcast outdoor / studio softbox.
3. **Render the existing pass-8 fitted body** (measurements already match the target subject) from front (0°), side (90°), and back (180°) at high resolution. Pass-7+8 already produces 8-view renders so this is configuration, not new pipeline.

Pass succeeds when the rendered body has visible skin coloration (not uniform peach plastic) and even lighting that doesn't conceal mesh defects.

## What I will do (step-by-step, in order)

1. **Extract UVs from `char.blend`** via a second one-shot Blender script. Writes `data/charmorph_female_uvs.npz` containing per-vertex UV coords (matching our 18,210-vertex order). One-shot like the base extraction — Blender is not a runtime dep.
2. **Verify UV ↔ vertex correspondence.** Bounds check: 0 ≤ u, v ≤ 1 for all entries.
3. **Triangulate UV array** in the same (i,j,k)+(i,k,l) pattern that `_load_faces()` uses, so per-face-corner UVs are consistent.
4. **Load `albedo.png`** as `PIL.Image` in `render_quality.py`.
5. **Pass texture + UVs into the pyrender mesh** via `trimesh.visual.TextureVisuals` with the appropriate UV array, then `pyrender.Mesh.from_trimesh(..., smooth=True)`. The `MetallicRoughnessMaterial` gets `baseColorTexture=PIL.Image`.
6. **Rewrite the light rig in `render_views_quality`:**
   - `ambient_light=(0.55, 0.55, 0.55)` (was 0.18)
   - Replace 3-point key/fill/rim with 4-light evenly distributed at modest intensities (each ≈ 1.5)
   - Place lights at the four "corners" of the camera ring at +30° elevation: front-left, front-right, back-left, back-right
   - No rim light specifically; the back-quarter lights provide some edge separation but nothing harsh
7. **Update `configs/subject_a_fitted.json`** to enable `render.texture: "external/CharMorph-db/characters/mb_female/textures/albedo.png"`.
8. **Re-run `scripts/build_body.py configs/subject_a_fitted.json`** producing 8-view output. Front (0°), right side (90°), back (180°), left side (270°) are the four cardinal angles requested.
9. **Inspect rendered front + side + back** and report observations.

## What I cannot do in this pass (honest list)

- **Hair.** No hair geometry; CharMorph ships hair as a separate `.blend` we haven't touched. Adding hair would be its own pass — UV-mapped hair card geometry, hairstyle selection, color, fit to the morphed head. Out of scope.
- **Bikini / clothing.** No clothing geometry. CharMorph has clothing assets but applying them requires per-body fitting (their `Realtime asset fitting`), which adds another pipeline stage. Out of scope.
- **Facial identity match.** The face is the MB-Lab neutral female. Head identity coefficients (positions 20–39 of the 45-dim identity) are zero. Matching a specific person's face needs either facial-fitting code or manual head-morph tuning. Out of scope.
- **Skin tone match.** The albedo texture has its own baked-in skin tone (Caucasian medium). I can tint it post-load with a multiplier if the rendered tone is too pale/dark vs the photo, but I can't bake-in tan lines, makeup, or specific pigmentation.
- **Subsurface scattering** (the warm translucent quality of real skin at ears, nose, fingers). pyrender's PBR doesn't support SSS. Would need switching to Blender Eevee or a custom shader. Out of scope.
- **Match makeup, lipstick, freckle pattern, blush.** CharMorph provides freckle/blush/lip masks but they require multi-texture compositing in a custom shader. pyrender's stock material is single baseColor. Out of scope.
- **Pose.** Still T-pose-with-A-pose-slight-arm-angle. Pose authoring is a separate pass.
- **Eye color / iris detail.** Eye geometry is on the mesh but separate iris/sclera textures would need separate material assignment per submesh. Skipping; eyes render as part of the skin.
- **Smile / expression.** Face expression coefficients (72-dim) are zero; the face is neutral. Could be set via morph_values but I'm staying scoped.

## Approach

### Stage 1 — UV extraction

`scripts/extract_charmorph_uvs.py` (runs once under headless Blender):
- Open `char.blend`, find the `mb_female` mesh object
- Get the active UV layer (Blender's `mesh.uv_layers.active.data`)
- For each loop (face-vertex), read `uv.x, uv.y`
- Cross-reference loop indices to per-vertex UVs (one vertex can have multiple UV values at seams; we pick the dominant one or store per-face-corner)
- For simplicity v1: take the FIRST UV per vertex (most vertices have a single UV; seam vertices will have a minor visual artifact at the seam, acceptable)
- Output: `data/charmorph_female_uvs.npz` with `uvs: (18210, 2)`

Triangulation: when we triangulate quads (i,j,k,l) → (i,j,k)+(i,k,l), the per-vertex UVs index by the same vertex IDs, so no re-mapping is needed.

### Stage 2 — Renderer updates

`src/render_quality.py`:
- New optional arg `texture_path: Path | None = None` and `uvs: np.ndarray | None = None`.
- If both supplied: load PIL Image, attach via `trimesh.visual.TextureVisuals(uv=uvs, material=trimesh.visual.material.PBRMaterial(baseColorTexture=image))`, then `pyrender.Mesh.from_trimesh(mesh, smooth=True)`. Pyrender will pick up the textured material automatically.
- Rework lighting:
  - `ambient_light` raised from 0.18 → 0.55 (about 3×) — fills shadows
  - Replace 3-point (key 3.0 / fill 1.8 / rim 2.2) with 4 directional lights at 1.5 each, placed at relative angles `[deg-45, deg+45, deg+135, deg-135]` from the camera, all at +25° elevation above camera height
  - Skin roughness tuned slightly (0.55 → 0.50 — albedo provides visual variation now)

### Stage 3 — Config + run

`configs/subject_a_fitted.json` gets a `render.texture` field. Default false; flip on for this pass.

### Stage 4 — Inspect + report

Read front/side/back/3-quarter renders. Verify:
- Texture is mapping correctly (no obvious UV breaks / wraparound seams in visible areas)
- Lighting is bright and flat (no deep shadows, no overexposed highlights)
- Body proportions still match target measurements

## Alternatives considered

1. **Skip texture, just lighting.** Quicker but doesn't address the "looks like plastic" problem. The whole point of `albedo.png` is to make the body look skinned. Worth doing.
2. **Blender Eevee render instead of pyrender.** Better lighting model (SSS, contact shadows, image-based lighting). But Blender headless render setup is its own pass — extra 1-2 hours of debugging compared to pyrender which already works.
3. **Bake the full CharMorph multi-texture shader to a single composite albedo.** Would mix in freckles/blush/lip color into one pre-baked texture. Multi-hour task; deferred. Stock albedo is sufficient for v1.
4. **Use displacement.png as a real displacement map.** Pyrender doesn't support tessellation-based displacement. Could pre-displace verts at load time, but the morphs already deform the mesh — applying displacement on top might fight the morphing. Skip; possibly revisit if surface detail is missing.

## Risks & open questions

- **UV layer presence.** Almost certain — CharMorph-db ships albedo.png + lipmap.png and references them via the .blend's shader nodes. UVs must exist.
- **UV seam artifacts.** With "first UV per vertex" simplification, the texture will be slightly misaligned at UV seams (e.g., where the mesh wraps from one side of the body to the other). Standard issue; usually shows as a faint line. Mitigation: if visible, switch to per-face-corner UVs by loading the trimesh with `process=False` and assigning `mesh.visual.uv` after triangulation.
- **Pyrender baseColorTexture + smooth shading.** Should work cleanly. If material doesn't take, fall back to per-vertex color (loses texture detail).
- **Brightness over-correction.** Ambient 0.55 might wash out the body. Will inspect; tune if too flat.
- **PIL import.** Already used in `render_quality.py`; no new dep.

  - Body skin colored from the texture (not flat peach)
  - No deep shadows / no over-bright highlights
  - Recognizable as a person with anatomical features still visible
